## extra
- 协议版本主线在变：chiaki-ng-core（versions.hpp:33-51）对 PS5 默认用 Takion v20，并协商 {12,15,18,20}；旧 C 库写死 v12。自研客户端应该实现 TAKIONPROTOCOLREQUEST 版本协商，不要写死某个版本；协议实现最好以 core 的 C++ 实现为准来对照。
- PS5 会在会话中自适应切换分辨率：STREAMINFO 里下发多个分辨率档位（各自带视频头），AV 包头用 3 位 adaptive_stream_index 指示当前档位（takion.c:1811，videoreceiver.c:158-170）。客户端的解码器和渲染器必须支持会话中途换分辨率、换 SPS/PPS。
- 丢包上报是 PS5 侧码控的主要输入（#230，nowrep）：上报丢包会让主机增加 FEC，丢包严重时大幅降码率而且恢复很慢。chiaki-ng 默认把上报截到 5%，这是「稳定」设计里最关键的可调参数之一，可以考虑按链路类型（局域网 / 公网 / 中继）分别设置。
- v1.10.1 的发布说明列了多项稳定性修复（丢失关键帧后恢复而不是冻结、重发更多丢失的包、修复丢包后掉帧、direct frame mapping 默认开启、修复帧节奏和渲染器问题），说明 2026 年内传输层和显示层都还在频繁修补，直接 fork 旧 C 库需要跟进这些修补。
- 即使完全不走 Sony 中转，注册仍需要 PSN Account ID（可以登录 PSN 获取，也可以用公开查询；docs/setup/configuration.md:112），PS5 端也要开启远程游玩。saawant12/orbit-play-ps5 支持从未关联 PSN 的本地账户，但要求 PS5 已越狱。
- 已有现成的 Web 网关可参考（Chiaki-NG-Web 的 WebSocket 套接字中继、ps5web 的 libchiaki 加 WebSocket 桥、psrp-web 的 WebCodecs 前端）。它们证明了「家中节点终结 Takion，再用 TCP/WebSocket 穿出去」这条路可行，但走 TCP 有队头阻塞，对稳定性有利也有弊，需要实测；它们大多是 AGPL。
- portal-boost 的实测经验可以直接用在中继设计上：PS5 接受任意源端口的 9296/9297 流；中继给视频和输入分别打 DSCP（AC_VI / AC_VO）；UDP 缓冲压到 256KB，让旧视频帧在中继上直接丢弃、不排队；多一跳 Wi-Fi 增加约 4 到 7ms。
- 许可证风险：chiaki-ng 是 AGPL-3.0-only 加 OpenSSL 例外，没有应用商店例外；core 和 swift 是 AGPL-3.0-or-later，带应用商店例外，但贡献要签 FLA。维护者正在积极追查闭源衍生品，并明确把「用 AI 照着翻译源码」视为衍生作品。自研时如果参考或移植 chiaki 代码，需要整体按 AGPL 开源；想闭源的话，只能基于独立的协议文档做净室实现，而且要能证明来源。
- chiaki-ng 的 LaunchSpec 里有几项写死的值（bwLoss 0.001、ports [53,2053]、按 Senkusha 测得的 mtu 和 rtt 填写；launchspec.c:24-28）。Senkusha 测出的 MTU 和 RTT 会进入主机的初始码控决策，自研时要保证测量准确，或者允许手动覆盖。
- ForWard Technologies（Pylux 的作者）被 core README 列为「提供远程串流协议」的贡献方，streetpea 也声明代表它主张 PSStream/Pylux 的权利。Pylux 是另一个值得关注的 AGPL 多平台实现（2026-08 之后没有推送）。
